# WFH Attendance System

A web-based attendance application for employees working from home. Employees can submit their daily attendance along with a photo as proof, while HRD can manage employee information and monitor attendance records.

This project was developed as a take-home assignment for a Full Stack Developer position.

## Usage

The application has two roles: Employee and HRD.

**Employee**
- Log in to their account.
- Submit daily attendance with a photo and optional notes.
- View their previous attendance records.

**HRD**
- View attendance summaries and recent submissions.
- Add, edit, deactivate, and reactivate employee records.
- View attendance records and filter them by employee or date.
- Open submitted attendance photos.

## Get Started

### Requirements

Make sure you have the following installed:

- Node.js and npm
- MySQL Server 8.0 or later
- Git

### 1. Clone the Repository

```bash
git clone https://github.com/C3L4N4/WFH-Attendance.git
cd "WFH Attendance"
```

### 2. Set up the Database

Create a MySQL database:

```sql
CREATE DATABASE wfh_attendance;
```

### 3. Configure the Backend

Go into the backend folder and install the dependencies:

```bash
cd backend
npm install
```

Create a `.env` file using `.env.example` as a starting point.

Update the database connection and other environment variables with your own values.

```env
PORT=3000
DATABASE_URL="mysql://root:YOUR_MYSQL_PASSWORD@localhost:3306/wfh_attendance"
JWT_SECRET=your_own_secret

SEED_EMPLOYEE_EMAIL=employee@example.com
SEED_EMPLOYEE_PASSWORD=your_employee_password

SEED_HRD_EMAIL=hrd@example.com
SEED_HRD_PASSWORD=your_hrd_password
```

Run the database migrations and generate the Prisma client:

```bash
npx prisma migrate deploy
npx prisma generate
```

To create the initial employee and HRD accounts, run:

```bash
npx prisma db seed
```

Start the backend:

```bash
npm run start:dev
```

The backend will run at `http://localhost:3000`.

### 4. Configure the Frontend

Open another terminal and navigate to the frontend folder:

```bash
cd frontend
npm install
```

Create a `.env` file using `.env.example`:

```env
VITE_API_URL=http://localhost:3000
```

Start the frontend:

```bash
npm run dev
```

The frontend will be available at `http://localhost:5173`.

## API overview

The backend exposes the following main endpoints:

| Method | Endpoint | Description |
|---|---|---|
| POST | `/auth/login` | Log in |
| GET | `/auth/me` | Get the current user |
| GET | `/employees` | Get employee records |
| GET | `/employees/:id` | Get an employee |
| POST | `/employees` | Create an employee |
| PATCH | `/employees/:id` | Update an employee |
| PATCH | `/employees/:id/deactivate` | Deactivate an employee |
| PATCH | `/employees/:id/activate` | Reactivate an employee |
| POST | `/attendance` | Submit attendance |
| GET | `/attendance/my` | Get the current employee's attendance |
| GET | `/attendance` | View attendance records |
| GET | `/attendance/:id` | View an attendance record |
| GET | `/attendance/:id/photo` | View attendance photo |

Access to certain endpoints depends on the user's role.

## Attendance Rules

A few rules are enforced by the backend:

- Each employee can submit attendance once per day.
- The attendance date and time are generated by the server using the Asia/Jakarta timezone.
- A photo is required when submitting attendance.
- Accepted image formats are JPG, PNG, and WebP.
- The maximum upload size is 5 MB.

## Notes

- Attendance photos are stored locally in the backend's `uploads/attendance` directory.
- Environment files containing local configuration and credentials are not included in the repository.
- The application is currently configured for local development. A production deployment would need additional configuration for hosting, file storage, and security.
